# Plan: Write docs/RANDOMNESS.md

## Context

The 100 Days RPG currently randomizes events turn-by-turn (via `sampleEventsForTurn`) and uses a seeded Mulberry32 RNG that's already threaded through `TurnEngine`. However, each playthrough follows the same structural skeleton: the same NPC encounter slots, the same merchant locations, the same location flavour text rotation. This document design formalises a set of complementary systems that use the **run seed** to differentiate playthroughs at a structural level — not just in moment-to-moment dice rolls.

The deliverable is `docs/RANDOMNESS.md`, a design document (no implementation yet). It should be precise enough for a developer to implement any feature from it without needing a follow-up conversation.

## What to write

### Foundations to acknowledge (already in the code)

Before designing new features the doc should orient readers on what's already in place:

| Thing | Where |
|---|---|
| Mulberry32 seeded RNG | `src/engine/Random.ts` — `nextMulberry32(state)` |
| `seed` + `rngState` on `GameState` | `src/engine/types.ts:420-422` |
| `rngState` threaded through TurnEngine | `TurnEngine` constructor accepts `randomOverride?` |
| `sampleEventsForTurn(state, rng)` | injectable rng parameter already present |
| `firedEventIds: Set<string>` | one-shot event deduplication |
| `randomTexts: string[]` on `Location` | per-location flavour pool, already defined |
| `eventPool?: string[]` on `Location` | per-location event override already in schema |

The RNG helper to use throughout: call `nextMulberry32(state.rngState)` to get `{value, state}`, then save the new state back. For run-layout decisions (NPC slots, shortcuts, merchant locations) use a **separate deterministic pass over the seed at run-start**, not the live `rngState`, so layout is stable regardless of how many rolls combat/events consume.

### Feature 1 — Day-Dependent Location Descriptions

**Problem:** Locations have `randomTexts: string[]` but nothing selects from them.

**Design:**
- Add a pure helper `pickLocationText(location: Location, dayNumber: number, seed: number): string` in `src/engine/GameState.ts`.
- Selection: `index = floor(mulberry32(seed XOR locationId XOR dayNumber).value * randomTexts.length)`. This is deterministic per (run, location, day) tuple without consuming live rngState.
- RoadScreen calls this when rendering the location description, replacing any static `locationText` display.
- No GameState change needed; no migration needed.

---

### Feature 2 — NPC Encounter Slots

**Problem:** Companion-meet and dialogue events fire probabilistically but have no structural placement; a player can go an entire run without meeting key NPCs.

**Design:**
Introduce `RunLayout` — a plain object computed once from the seed and stored on `GameState`:

```ts
interface RunLayout {
  npcSlots: Array<{ locationId: number; npcEventId: string }>;
  merchantLocations: number[];       // subset of locationIds
  activeShortcuts: Array<{ from: number; to: number; label: string }>;
  eliteSpawns: Array<{ locationId: number; enemyType: string }>;
}
```

`RunLayout` is generated by `generateRunLayout(seed: number): RunLayout` in a new file `src/engine/RunLayout.ts`.

For NPC slots: pre-define 15–20 candidate `{locationRange, npcEventId}` pairs in `RunLayout.ts`. Some additional candidates to include are:
- **Coron, the Wandering Priest** (Location Range: 15–30, ID: `coron_priest`): Offers blessing / healing in exchange for gold, or based on high reputation.
- **Sylas, the Shady Collector** (Location Range: 45–60, ID: `sylas_collector`): Offers to buy rare antiquities / artifacts from the player for a premium, or hints at treasure.
- **Griselda, the Herbalist** (Location Range: 70–85, ID: `griselda_herbalist`): Sells potions at a discount if the player shares food, or cures conditions.
- **Finn, the Quick-Fingered Kid** (Location Range: 35–50, ID: `finn_pickpocket`): A pickpocket encounter that interacts with the player's Stealing skill.

At run-start, the generator selects 5–7 of them deterministically (Fisher-Yates with seed-derived RNG), records the chosen `locationId` within each range. TurnEngine checks `state.runLayout.npcSlots` in `SamplingEvents` phase — if the player is at a slot location and the event hasn't fired, force-queue it (same pattern as boss events).

### Feature 3 — Traveling Merchant

**Problem:** Shops are fixed to `hasShop: true` locations. A merchant that appears at different locations each run creates discovery incentive.

**Design:**
`generateRunLayout` picks 3–4 locations (excluding permanent shop locations) as `merchantLocations`. TurnEngine (or EventSystem) treats arrival at a `merchantLocations` location identically to a `hasShop` location for that run. No new event type needed — wire it in the existing Trade action path in TurnEngine, gated by `state.runLayout.merchantLocations.includes(state.currentLocationId)`.

---

### Feature 4 — Roaming Elite Mobs

**Problem:** Combat events are purely probabilistic; there's no sense of a persistent threat occupying a stretch of road.

**Design:**
`generateRunLayout` picks 6–8 `{locationId, enemyType}` elite spawns from wilderness/dungeon locations (locs 15–110). Each is a one-shot combat event: when the player enters that location, if it's not in `clearedCombatLocations`, force-queue a `bandit_ambush`-style event tagged `'location_ambush'`. TurnEngine already handles `location_ambush` tag cleanup (see `TurnEngine.ts:128-131`). No new event definition needed; reuse the `combat_handler`.

The `enemyType` field guides which CombatEngine enemy to instantiate (13 types already in `CombatEngine.ts`).

---

### Feature 5 — Path Shortcuts

**Problem:** Every run traverses the same 125-location linear road. Shortcuts give faster players an occasional structural reward.

**Design:**
Pre-define 12 candidate shortcut pairs `{from, to, label}` in `RunLayout.ts` (e.g. `{from: 28, to: 34, label: "The old smuggler's pass"}`). `generateRunLayout` activates 3 of them. Shortcuts only appear as an additional Move option on `RoadScreen` when the player is at a `from` location **and** their Perception meets the feature's reveal threshold. Players below that threshold travel normally and never see the shortcut prompt. Selecting one moves the player directly to `to` and costs 1 extra food (forced march equivalent).

RoadScreen reads `state.runLayout.activeShortcuts.filter(s => s.from === state.currentLocationId)` and renders shortcut buttons only for players who satisfy the Perception gate. The Move action in TurnEngine needs a `shortcutTo?: number` param variant.

---

### Feature 6 — Steal Action

**Problem:** Players need more interactive choices at locations with NPCs (or in towns) to take calculated risks for immediate rewards.

**Design:**
- Render a **Steal** action button alongside **Talk** on the `RoadScreen` when `dialogueNearby` is true or `location.isTown` is true.
- Steal resolution in `TurnEngine.ts`:
  - Calculate success rate: `successChance = clamp(0.40 + stealingSkill * 0.03, 0.10, 0.95)`, where `stealingSkill` is a player stat that starts at `5`.
  - On success:
    - 60% chance to gain `5–15 gold`.
    - 40% chance to gain a random common consumable item from a pool (`dried_rations`, `hunters_jerky`, `healing_potion`, `spirit_tonic`). If inventory is full, fall back to gold.
    - Train Stealing skill: increase `stealing` stat by `1`.
    - Lower reputation: `-5` reputation delta.
    - Grant `4` XP.
  - On failure (caught):
    - No reward.
    - Lower reputation: `-10` reputation delta (higher penalty for being caught).
    - Lower morale: `-5` morale delta.
- The `Stealing` skill is trainable via levels (via the **Thievery** choice: `+3 Stealing skill`) and by successfully stealing.

---

### Data Model Changes

Add `runLayout: RunLayout` to `GameState`. Because `RunLayout` is fully re-derivable from `seed`, it can be omitted from `SerializedGameState` and reconstructed on load — or serialized as a plain object (simpler). Recommend serializing it to avoid re-running generation on every load.

`SerializedGameState` already `Omit`s the Set fields; `RunLayout` (all arrays/objects) serializes cleanly as-is.

Schema version: bump `SCHEMA_VERSION` from 6 → 7 in `src/engine/GameState.ts`. Add a migration case in `SaveEngine.migrate()` that generates `runLayout` from the loaded `seed` for v6 saves.
